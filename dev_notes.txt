v0.1 (2026-08-22)
- Project initialized. Directory structure created.
- Environment prepared: Go 1.27.0 + Rust 1.98.0 in tools/ (portable),
  Xcode CLT installed (clang 21, git 2.50.1).
- STACK DECISION: Swift 6.3 + SwiftUI + Swift Charts via CLT.
  Zero external dependencies - links only macOS system frameworks.
  Chosen for maximum native look/feel on macOS.
- DATA: Open-Meteo API (free, no key) - the free GitHub weather project.
  Current + hourly + daily (10 days) in one request; timezone=auto.
- UI v0.1: condition-tinted gradient background, hero card (big temp,
  feels-like, humidity/wind/gusts/UV/pressure/rain pills), horizontal
  10-day forecast strip (Weatherzone style, today highlighted), tabbed
  48h charts (Temperature area / Rainfall bars / Wind), sunrise+sunset
  footer, location menu with 10 presets (default Adelaide, persisted),
  manual refresh + 30-min auto-refresh.
- PACKAGING: dist/WeatherDashboard.app (592 KB) - standalone bundle,
  ad-hoc signed. build.sh rebuilds it. Runs on macOS 13+ Intel.
- VERIFIED: compiled clean, launched, live Adelaide data fetched,
  quit cleanly.

HOTFIX 1 (2026-08-22, still v0.1):
- BUG: app showed error state - no data. CLI curl worked, GUI didn't.
- DIAGNOSIS (via offline decode harness in temp/):
  1) Original failure: JSON keys are snake_case (temperature_2m) but
     Codable properties camelCase with no mapping -> keyNotFound.
  2) Attempted fix keyDecodingStrategy=.convertFromSnakeCase FAILED:
     on this macOS 26 Foundation that strategy is a NO-OP for plain
     property names AND MANGLES explicit CodingKeys raw values.
     (Regression vs older Foundation - verified with isolated tests.)
- FIX: removed the strategy entirely; added explicit CodingKeys enums
  to all API structs mapping snake_case JSON -> camelCase properties.
- LESSON: never rely on keyDecodingStrategy on this machine; always
  write explicit CodingKeys for external APIs.
- Re-verified: harness OK (10 days / 48 hours / 15.1C), app rebuilt
  (588 KB), relaunched successfully.

CHANGELOG v0.2 (2026-08-22)
--------------------------------------------------
- APP ICON: generated via CoreGraphics tool tools/gen_icon.swift
  (sky gradient + sun + cloud), iconset -> AppIcon.icns (658 KB),
  wired into Info.plist CFBundleIconFile. No design assets needed.
- CITY SEARCH: magnifier button in header opens search sheet;
  Open-Meteo geocoding API (debounced 300ms via .task(id:)).
  Results show region/country; picking a city adds it to the
  location menu and switches immediately. Custom cities persist
  in UserDefaults (JSON [Place]) - Place made Codable.
- AIR QUALITY + POLLEN: second Open-Meteo endpoint merged
  concurrently (async let). Pills appear when data exists:
  US AQI with label, max pollen grains with label.
  GOTCHA: API no longer accepts generic tree_pollen/weed_pollen
  in current (HTTP error) - use named species instead
  (grass, alder, birch, mugwort, olive, ragweed); tree = max of
  tree species. Air fetch is non-fatal: pills hide on failure.
- Version bumped: plist 0.2 (build 2). Bundle now 1.4 MB.
- VERIFIED: endpoints probed by curl, app rebuilt, relaunched,
  process stable.

v0.4 (2026-08-25, build 8)
- Milestone: outstanding-goals sweep (units toggle, dual-axis rain
  chart, menu-bar mini view).
- UNITS TOGGLE: TempUnit (°C/°F) + WindSpeedUnit (km/h/mph) enums in
  AppSettings, persisted (wd_temp_unit / wd_wind_unit). Data stays
  metric internally; converted at display time -> instant switching,
  no refetch. Applied to hero temp+suffix, feels-like, wind/gusts
  pills, day cards high/low/wind, temperature & wind charts (values +
  axis now in chosen unit). Unit hint badge added next to "Next 48h"
  title (°C | mm · % | km/h) since this SDK has no AxisTitle API.
- RAINFALL CHART DUAL AXIS: Swift Charts has no native dual scale ->
  probability line mapped onto the mm domain (percent * maxRain/100),
  trailing AxisMarks shows un-scaled % ticks at 0/25/50/75/100 with
  faint grid; leading axis keeps mm. Dashed line unchanged visually,
  now reads correctly against its own right-hand scale.
- MENU-BAR MINI VIEW: MenuBarExtra(.window) panel - location,
  condition desc, icon + big temp, feels-like/wind/humidity rows,
  updated time, refresh button, "Open dashboard" (openWindow(id:)).
  Dynamic status-item label = condition symbol + current temp.
  WeatherStore moved to App-level @StateObject injected into both
  scenes (ContentView now @EnvironmentObject); auto-refresh timer
  moved INTO the store (30-min Task loop, load() guarded by
  isLoading) so both surfaces stay fresh; WindowGroup got explicit
  id "dashboard".
- KEEP-ALIVE OPTION: settings toggle "Stay in menu bar after closing
  window" (wd_menubar_keepalive, default OFF = legacy quit-on-close).
  applicationShouldTerminateAfterLastWindowClosed reads UserDefaults
  dynamically so toggling takes effect immediately.
- Settings sheet gained Units section (segmented °C/°F + km/h/mph)
  and the keep-alive toggle; new localized keys unitsHeader /
  stayInMenuBar / openDashboard in all four languages.
- GOTCHA: AxisTitle unavailable in this SDK's Charts -> replaced by
  header unit badges. Slow compile (~2min/slice) from chart type
  inference - expected, not a regression.
- VERIFIED: universal build OK (3.1 MB), launched, process stable
  >20s, no crash reports, clean SIGTERM exit.
